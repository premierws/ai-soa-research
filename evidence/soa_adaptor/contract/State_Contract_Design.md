# SOA Adaptor 通用状态契约与 AmbLiMgr 配置评审稿

版本：0.1-review。仅定义语义、能力组合与接口策略；不修改现有项目IDL、源码、配置。JSON为声明式评审模型，不宣称是已实现的生成器输入格式。

## 1. 分层与职责

- common_state_contract.json：所有实现共享的术语、状态取值、作用域及一致性规则。
- capability_profiles.json：七种可组合、可校验的使用场景模板，模板不代表所有接口都必须开启的能力。
- amblimgr_state_config.json：从现有IDL/源码映射得到的31个操作绑定，明确覆盖、排除、参数和实例差异。
- review_validation.json：本次配置一致性验证，不能代替底座生成及运行测试。

通用语义不是通用全量payload。只有接口配置需要暴露的状态，才进入VMBC消息或辅助通道。观察能力也不等于必须向应用暴露：Adaptor可监测连接以阻止旧命令重放，而应用只消费通信有效性。

## 2. 状态作用域

连接属于源服务实例，而非整个Adaptor。E2E与样本状态属于具体RPC及接收操作。投递失败属于具体消费者绑定。需要事务时，状态属于具体请求标识。

绑定唯一键包含consumer、source_package、service、instance、rpc、operation与内部目标；部署通信域、Core和ASIL边界参与实例划分。不得因为Service名相同就混合不同实例、请求来源或安全分区。

## 3. 通用语义

| 概念 | 含义与约束 |
|---|---|
| bridge_lifecycle | Adaptor自身生命周期；READY不等于平台已连接 |
| source_connection | 源服务实例的连接状态；UNOBSERVED不冒充CONNECTED |
| sample_presence | 无样本、本连接周期样本、旧连接保留样本；存在旧值不等于当前有效 |
| e2e | 未配置、未观测、通过、失败、超时；未配置不是通过 |
| freshness | 未监测、未观测、新鲜、过期；必须有明确阈值和刷新依据才能判过期 |
| forward_phase | 本地接收、平台提交、应答、失败、超时、取消；平台提交不代表业务成功 |
| error_event | 一次错误观测；累计错误和最后错误不代替当前健康状态 |

平台原始码另附raw_code、raw_known、code_domain，通用状态通过显式映射得到；映射版本与底座版本绑定，不假定0总是正常。

桥接data_valid是配置派生结果：bridge_ready、存在策略允许的样本，以及接口要求的连接/E2E/freshness条件全部满足。它独立于accr_pedl_posn_vld等业务字段。

## 4. 时间、序号和一致性

source_epoch仅表示源连接周期；重连会改变。sample_seq与last_valid_receive_time只在接受新的源样本时更新；缓存重放不刷新。跨重启恢复需清空消费者序号基线，不把epoch当作永久唯一ID。

本地接收时间只在所属单调时钟域解释，不能直接与其他ECU的时间戳相减。32位时钟需明确回绕规则和支持的最大时间间隔。

业务值与对应元数据须形成一致快照，且只由配置指定的单写者提交。状态变更可以独立通知；无效状态通知不伪造新的业务值。E2E必须关联到具体源消息，不能以最新状态证明整段History Queue有效。

## 5. 按需能力与暴露方式

能力包括连接观测、接收E2E、时效监测、错误报告、请求跟踪、响应交付、快照重放。通用默认关闭，由profile与绑定显式启用。

暴露方式可选：不暴露、复用现有内置接口、业务消息元数据、状态Event、错误Event、带关联的结果Event。生成器根据选中能力生成必要字段；不强制每个服务生成BridgeStatus/BridgeError/Refresh三套RPC。

新应用接入时需要重放，但底座不提供可验证的重放触发时，配置必须显式选择刷新FF或其他接入机制；不能默认为普通Event自带历史首值。本轮只定义重放语义，不在缺少SDK依据时锁定具体辅助RPC及编号。

## 6. 七个使用模板

| 模板 | 默认内部形态 | 使用条件 |
|---|---|---|
| rx_state | Event | 消费状态，允许按源QoS使用缓存；不默认开启时间过期 |
| rx_state_e2e | Event | 在rx_state上启用逐消息关联的E2E；接纳失败值的规则显式定义 |
| rx_event_sequence | Event | 每条事件均有意义，采用有界FIFO，禁止以最新值覆盖 |
| tx_ff | FF | 单向请求或Field Set；无业务应答，无自动重试，断连不重放旧命令 |
| rr_transaction | RR | 业务依赖本次结果；有界并发、关联、超时和迟到响应策略 |
| ff_with_result_event | FF+结果Event | 形式统一，但仍完整保留事务语义 |
| query_on_demand | Get/RR | 查询必须得到本次请求对应结果，禁止旧缓存冒充新查询结果 |

模板继承只减少重复声明，不允许绕过语义校验。批量配置的最终结果应输出展开后的逐绑定配置供评审。

## 7. 阻断不合法组合的规则

1. 所需状态无法从源API得到时失败，不静默标正常。
2. 无E2E配置不能启用接收E2E校验；源发送保护和接收校验分开处理。
3. ON_CHANGE不自动意味着超时；需要监测必须明确阈值、时钟和保活来源。
4. 每条必处理的事件/命令禁止latest_value覆盖；队列深度和满处理必须完成实际解析。
5. 业务需要结果时，纯FF无反馈配置不合法。
6. 请求重试必须有幂等/去重依据、有界次数和有效期。
7. 只发请求却需要反向状态时，必须选择状态回传通道，不能把状态塞进请求数据。
8. 任何消息字段、类型、辅助RPC的生成均遵循namespace、编号和冲突检查。

## 8. AmbLiMgr 的具体选择

- 原有9种服务、12个实例、31项操作：普通接收6项、E2E接收3项、FF发送22项。
- 所有12个活动源实例在Adaptor内观测连接；仅动态灯光与四个静态灯光实例需要将原始连接状态/原因及重连变化交给原业务。对其他实例，连接用于通信有效性与发送控制，不强制向业务公开原始连接码。
- 三个E2E项：RlsInfo.LightSnrSts=250ms；VehState.VehStateInfo=100ms；MotionCtrlInfoPri.IfCommInfo=100ms。超时信息来自平台IDL及框架E2E，不额外给所有消息添加新鲜度超时。
- 所有接收保留业务字段，与桥接通信有效性分开。读失败或本方案建议的E2E接纳失败不更新旧业务值，状态标无效。E2E这部分为拟增加并验证的策略，不能宣称原应用已显式实现；也不擅自新增置零或关灯动作。
- 初值必须来自接纳的源消息；本连接周期缓存可重放，旧连接缓存不得冒充恢复后的新值。
- 五个控制实例在重连后由应用沿用原控制重发逻辑。22个FF不新增自动重试，不在恢复后回放旧队列命令。提交前再次检查连接。
- 源与本地队列配置在集成中解析，保留原消息/命令语义；尚未解析前不宣称队列行为已冻结。
- DynPrmSet.seg_node_pri继续由Adaptor补NO_REQ；不因状态契约改变此前字段映射。
- 五项未找到业务使用的接收接口以及涉及的原错误回调没有获准删除；在迁移前确认外部用途，或保持原路径。它们不混入31项已确认业务绑定。

调度仍为10ms的输入转发→原应用→输出转发。输入提交至应用缓存的时机需要本地框架验证；不能只凭调用顺序假定异步回调已完成。

## 9. 最小验收矩阵

- 所需能力关闭时不生成无用payload或辅助RPC。
- 同服务不同实例状态独立；同源多个消费者投递状态独立。
- 首次接入、晚接入、源重连、本地Adaptor重启均不接受伪造初值。
- E2E失败不更新正常样本状态；被过滤的相同有效样本仍更新接收健康时间。
- 状态型与逐条事件型队列行为分别验证；满队列有可观测错误或拒绝。
- FF局部成功不被解释为平台业务成功；RR保留关联、超时和迟到处理。
- 每个配置的连接/E2E/freshness条件均能追溯到实际输入与测试，不以生成代码通过代替验收。

## 10. 本轮交付边界

已给出语义模型、七种模板与AmbLiMgr全部31项绑定，并校验模板继承、唯一键、3项E2E参数和22项无应答/无重试策略。未修改正式项目文件，未修改IDL，未运行底座集成或目标测试。

ASIL、Service ID、真实SDK状态映射、已解析QoS和状态承载方式仍是后续落地输入。这些不改变本轮通用状态定义，但必须在生成正式运行产物前绑定，不能用未解析占位值宣布完成。
