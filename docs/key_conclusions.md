# 车控 Agent 阶段性关键结论

研究日期：2026-11-12。本文为完整报告的阅读入口，证据定位见 [对应表](../evidence/evidence_matrix.md)。

## 1. 业务目标

**开放受约束的目标组合能力，复用系统产品的执行能力，让 VCC 对其承接的 Mission 形成完整责任。**

车控 Agent 面向已知、有限的车辆能力，既能执行预定义场景，也能针对需求在边界内形成新场景。它负责当前车辆能否承接、如何协调以及最终是否满足目标。

“任意组合”指不必提前穷举所有场景，不代表任意动作、无限权限或凭空产生新功能。

## 2. 能力、场景与 Mission

- 能力是具有稳定业务语义、输入边界和结果语义的功能。
- 场景是一组目标及其关系，可以预定义、参数化或动态组合。
- Mission 是某一次被实际承接的任务，有对象、约束、生命周期和结果。

同一个场景可以执行多次，产生不同 Mission。动态生成一次场景并不等于已经形成通用产品能力。

## 3. VCC 与系统产品边界

VCC 承担车控相关的整体目标、跨系统协调、任务仲裁、生命周期与完成判断。系统产品继续负责本域策略、时序、状态机、实时闭环、诊断和保护。

功能是否归属 VCC，应看是否需要统一任务责任，而不是机械统计调用了几个服务。统一入口不意味着把单系统实现迁入 VCC。

例子：VCC 提出二排热舒适改善目标；具体风量、出风温度和设备策略由相关系统产品决定。

## 4. 多 Agent 分工

| 角色 | 核心职责 |
| --- | --- |
| 座舱 Agent | 理解用户需求、偏好、对象和对话，完成必要澄清 |
| 智驾 Agent／世界模型 | 理解车外态势，提供事实、预测及其职责内的协同目标 |
| 车控 Agent／VCC | 理解车辆能力和当前条件，承接车控 Mission，进行协调与结果闭环 |
| 系统产品 | 完成本域目标的策略、执行和保护 |

车控相关跨系统场景编排与目标仲裁放在 VCC 更合适；语义歧义由交互方澄清，域内仲裁和实时保护仍有各自归属。导航、内容业务和智驾运动控制权限不因引入 VCC 自动迁移。

## 5. 对外接口应兼容不同使用方

座舱、智驾、手机和传统控制入口都可能成为消费方。对外支持精确控制、相对控制、效果目标、预定义场景、结构化目标组合、状态和能力查询等形态。

调用者是不是 Agent，不决定请求必须模糊还是精确。精确控制不必经过 LLM，模糊目标也应有结构化、明确的执行语义。

## 6. 动态场景的表达

通过稳定任务入口传递一组有类型的目标、共同约束和偏好。预定义的是可组合能力与表达规则，不是每一种组合。

例子：“二排右侧稍暖，灯光稍暗，不改变前排，尽量省电。”表达为热舒适目标、灯光目标、前排保持约束以及省电偏好。无需新增专用场景编号，也不要求上游掌握底层 RPC。

硬约束不满足时说明冲突、拒绝或澄清；不能为了满足软偏好或某个目标而静默突破。

## 7. 对内编排以目标与结果为中心

VCC 协调目标依赖、资源冲突、任务抢占和整体降级。能复用系统完整能力时优先复用，避免为每个场景重写域内脚本。

现有动作与状态可以继续保留；必要时补齐系统侧目标适配和结果反馈。soa_adaptor 继续负责通信和 IDL 桥接，不承担 Mission 规划。

## 8. 接受与完成必须分开

任务被接受、请求已发送、系统已接受、执行中和目标已达成具有不同含义。FF 写成功不是业务完成，RR 成功返回也需查看其具体语义。

VCC 应给出整体和子目标结果、失败或降级原因以及可用证据。没有请求关联和可靠完成证据时不能伪造确定性。

## 9. 任务退出和持续性要明确

一次性设值与持续维持目标不同。取消任务不等于撤销已发生的动作，恢复基准和恢复范围也不能默认可逆。

这已是明确的语义要求，具体状态枚举和策略尚未定版。

## 10. 场景持续演进

优先复用适用的已知场景，必要时参数化或局部重组，再在能力范围内生成新组合。执行和使用反馈可沉淀为个人已知场景，伴生再汇集为产品规划输入。

候选组合、一次 Mission、个人场景和产品预定义场景应分别管理。只保存动作日志不足以理解需求，应保留目标、上下文、约束与结果。

## 11. SOA 复用与提升

已有服务提供执行基础；部分能力已经接近目标型表达，应优先复用。服务名、RPC 类型和接口数量不能单独证明完整能力。

service_arch 可以支撑能力到服务、实例和版本证据的追溯，但静态 IDL 无法自动推导控制政策、运行时可用性或物理完成条件。

## 12. 协议不替代业务契约

MCP、A2A 和现有 SOA 可以在不同层次承担接入和协作。业务目标、权限、任务和结果语义需要先明确。当前没有决定全面替换 SOA，也没有决定必须使用某个 Agent 协议。
