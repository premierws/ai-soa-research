## 2. 六个能力建设方向

1. 能力模型和目标、结果、上下文契约。
2. 面向 Agent 与传统使用方的交互架构。
3. 既有服务和接口的能力提升方法。
4. 中间件与底软功能性能需求。
5. 可复用工程工具和公共机制。
6. 面向目标与契约的验证方法。

详细内容见 [能力方向](02_capability_and_platform_directions.md)。这些是建议的能力版图，不是同时启动全部项目的承诺。

## 3. 已被后续澄清替代的理解

- 不再以旧规划工作的逐项升级为新规划主线。
- 不将矩阵定义为统一承接车控 Agent 开发的工程中心。
- 不要求 DO 全程参加所有研究议题。
- 不用车型节点和交付进度作为 COE 的主要运作方式。
- 早期“平台交付”表述，收敛为共性技术能力建设、资产可采用以及工程承接界面清楚。

## 4. 仍需进一步明确

| 议题 | 待明确内容 |
| --- | --- |
| 正式定位 | 组织名称、章程、服务范围与已有组织的边界 |
| 核心成员 | 哪些团队提供稳定代表，参与投入如何保障 |
| 授权 | 哪些可形成 COE 技术决策，哪些需进入既有治理机制 |
| 资产维护 | 规范、样例、工具和公共机制由谁持续维护 |
| 首批议题 | 选择哪些真实业务问题作为切片，如何避免范围过大 |
| 平台边界 | 哪些只是方法与参考实现，哪些需要产品化工具或组件 |
| 验证 | 与现有测试责任方的接口、环境及能力基线 |
| 评价 | 怎样评价采用效果、复用和问题解决，而非只统计会议和文档 |

当前没有确定成员名单、预算、排期、最终协议或正式组件清单。后续讨论应在本次 COE 定位上继续细化。
