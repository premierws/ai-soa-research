# 待继续讨论的问题

以下是截至 2026-11-12 尚未冻结的业务与契约议题，不构成当前开发计划。

| 议题 | 需要明确的内容 | 已有判断边界 |
| --- | --- | --- |
| 能力集合 | 首批支持哪些目标、精确命令与场景 | 只能组合真实存在且具有责任主体的能力 |
| 模糊目标 | 稍暖、安静、舒适如何解释与评价 | 不能只用模糊字符串替代业务语义 |
| 目标完成 | 一次达到、持续维持、部分成功和未知结果 | 通信成功与业务完成分开 |
| 控制权 | 多乘员、远程、手动操作、自动场景之间的覆盖关系 | 身份与授权来自可信接入，仲裁分层 |
| 组合规则 | 并行、依赖、互斥、共享资源和冲突处理 | 硬约束不允许静默突破 |
| 生命周期 | 修改、暂停、抢占、取消、恢复和终止 | 取消不等于物理撤销，恢复策略需明确 |
| 证据 | 请求关联、状态来源、时效、质量与结果证据 | 不把旧 buffer 读取当作新帧，不伪造 E2E 状态 |
| 个人场景 | 保存条件、版本、车型适用性和失效处理 | 候选与已验证场景分开 |
| 伴生产品化 | 如何从个性化使用归纳通用场景 | 一次成功不等于产品能力 |
| 上下文 | 事实与预测的来源、时效、可信度和授权关系 | 世界模型预测不是控制许可 |
| 协议 | 现有服务、MCP 或 A2A 如何适配不同消费者 | 先稳定业务语义，协议尚未选择 |
| 功能边界 | 原规划中跨域时序与子系统执行的精确定义 | VCC 协调跨系统目标，本域控制继续留在产品 |

原文图片、白板和部分关联文档尚未完整审阅，正式设计时还需要结合功能责任方确认。当前材料足以支撑阶段性研究归档，不等同于已经完成所有功能评审。
