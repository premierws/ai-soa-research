# 最新讨论基线：车控 Agent 与服务架构矩阵

更新日期：2026-11-16。用于索引此前讨论后的关键澄清，不改写历史记录。

## 1. 战略与方案分层

参考《从 SDV 到 AI-DV》的方向，将战略愿景、能力蓝图与实施承诺分别表达。SDV 是产品与研发范式，SOA 是重要架构基础之一。当前研究以既有 SOA 为核心积累，不把战略图中全部能力视为已具备或必须同时自建。

实施事项需要业务范围、可行方案、责任团队、投入、环境和验证依据。缺少承接的事项可以保留为研究方向，不列入实施承诺。

## 2. 车控 Agent 价值与必要性分别论证

智能车控的业务价值包括：覆盖能力范围内未被逐一预定义的需求，减少用户操作与协调，沉淀个人场景并支持产品演进。收益需要通过真实任务验证。

这些价值不天然证明必须设立独立车控 Agent。应分开判断：

1. 跨入口、跨系统缺口证明共同协调职责的需求。
2. 整体 Mission 责任、复用与独立演进价值，支持论证独立 VCC 边界。
3. 运行时方案选择、动态组合和重规划的净收益，支持论证 Agent 化。
4. 是否使用大模型，依据具体环节收益、代价和验证条件决定。

优先评估现有系统扩展，采用确定性机制与规划能力的合理组合。系统产品保留本域执行和保护。

## 3. 矩阵的最终范围澄清

用户明确：整体软件架构由另一个独立虚拟组织运营。本矩阵仍围绕现有服务架构能力扩展提升，SOA 是最重要的基础设施和核心 know-how。

当前定位为：以 SOA 服务架构能力为基础，持续提升车辆能力抽象、交互契约、服务协同与验证能力，支撑车控软件和智能化应用建设。

不采用此前一度提出的、覆盖整体车控软件架构的广泛能力中心定位。

| 主体 | 主要责任 |
| --- | --- |
| 服务架构矩阵 COE | 服务／能力抽象、交互与结果契约、服务提升、SOA 与底座需求、验证方法 |
| 独立软件架构矩阵 | 软件职责、模块结构、运行与部署架构及整体软件体系安排 |
| VCC 和业务团队 | 场景、任务协调与承接 Mission 的整体结果 |
| 系统产品 | 本域能力承诺、执行策略、控制与保护 |
| 工程与项目组织 | 对应实现、集成、发布、资源与交付承诺 |

矩阵保持虚拟 COE、无强交付属性，但需要明确核心参与、资产维护及必要试验投入。角色继续采用 SO、FO、AI（车型架构）、平台及领域软件架构师、SWE、DO、TPM，验证等专业按议题参与。
